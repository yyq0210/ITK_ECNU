## 2. hybrid cast 链决策（任务 2）

**结论：放弃 cast 链 hybrid。**

依据：

- 2026-05-31 实测：hybrid 比 full_double **慢 0.80–0.97×**（cast 开销 > 收益）
- 本次实验：float vs double 精度差异为 **0**（滤波/分割算子），无「必须用 hybrid 保精度」的场景
- 示例代码 `hybrid_precision_demo.cxx` 已改为 **推荐 full_float**，hybrid 支路已移除

**例外：** 若未来某 pipeline 实测出现 float 不够而 hybrid 有精度收益，再单独评估；当前数据不支持使用 hybrid。

## 3. 滤波 / 分割全程 `Image<float>` 性能对比（任务 3）

**对比方式：**

- **full_float：** 读入 float → Filter\<float\>
- **full_double：** 读入 float → Cast→double → Filter\<double\>（模拟「误用 double pipeline」）
- **精度参考：** full_double；报告 float 相对 double 的 max_abs / rmse

|------|----------|-----------|--------|---------|
| RecursiveGaussian | 1.36 | 2.79 | **2.04×** | 0 |
| Median+RecursiveGaussian | 5.04 | 7.25 | **1.44×** | 0 |
| DiscreteGaussian | 2.86 | 3.72 | **1.30×** | 0 |
| OtsuThreshold | 3.77 | 5.00 | **1.33×** | 0 |

| 算子 | ms_float | ms_double | 加速比 | max_abs |
|------|----------|-----------|--------|---------|
| RecursiveGaussian | 10.65 | 10.61 | 1.00× | 0 |

### 3.5 滤波 / 分割小结

1. **2D 真实数据：** full_float 比 full_double 快 **1.24–2.07×**，精度 **完全一致**（max_abs=0）。
2. **推荐：** 滤波与 Otsu 分割 **全程 `Image<float>`**。
3. **double 路径慢的部分原因：** 含 **Cast float→double** 开销；若 IO 已是 float，直接用 float Filter 最省事。

## 4. Bilateral float vs double（任务 4）

参数：`domainSigma=4`，`rangeSigma=50`，96 线程，5 次平均。

| 分辨率 | ms_float | ms_double | 加速比 | max_abs | rmse |
|--------|----------|-----------|--------|---------|------|
| 214×256 | 64.0 | 64.5 | **0.99×** | 7.6e-6 | 3.6e-6 |
| 1024×1024 | 1111 | 1087 | **0.98×** | 7.6e-6 | 3.6e-6 |
| 2048×2048 | 3874 | 3793 | **0.98×** | 7.6e-6 | 3.6e-6 |

### Bilateral 小结

1. **速度：** float **未**比 double 更快（约 **0.98–1.01×**）。主因：Bilateral 在 `Image<float>` 下仍用 **`NumericTraits::RealType = double`** 做邻域/exp 运算（见 **§9**），并非全程 float SIMD。
2. **精度：** 存在 **极小** 数值差（max_abs ≈ **7.6×10⁻⁶**），对可视化可忽略；若需 bit-identical，保留 double。
3. **实践建议：** Bilateral **优先沿用 ITK 官方 Example 的 float** 即可（内存更省）；**不必**为加速专门改 double；也**不必**引入 hybrid。

## 5. 总体建议

| 场景 | 推荐策略 |
|------|---------|
| 滤波 / 分割（Gaussian、Median、Otsu 等） | **全程 `Image<float>`** |

## 8. 卷积类重算子（补充）

Bilateral、DiscreteGaussian、Mean、空间卷积、FFT 卷积的完整实测见 **[`操作记录_卷积重算子float_vs_double_2026-06-10.md`](./操作记录_卷积重算子float_vs_double_2026-06-10.md)**。

**要点：** 大图（1024²+）卷积类算子 float **不更快**（≈0.97–1.02×）；精度差约 **10⁻⁵**；用 float 主要为 **省内存**。  
**机理验证：** ITK 已开 **NEON**（`-march=armv8.2-a+crypto -O3`），但 Filter 内部 **`RealType=double`**，objdump 见 **`fmla v*.2d`** 而非 float 4 路 — 详见卷积报告 **§8**。

## 9. 向量化与 RealType 验证（摘要）

完整命令与反汇编见 [`操作记录_卷积重算子float_vs_double_2026-06-10.md`](./操作记录_卷积重算子float_vs_double_2026-06-10.md) **§8**。

| 验证项 | 结果 |
|--------|------|
| ITK `build-yyq` 编译 | `-march=armv8.2-a+crypto -O3`（NEON 已启用） |
| `precision_*_bench` 编译 | 无 `-march`（热路径在 ITK 库内，影响可忽略） |
| Bilateral `objdump` | **`fmla v*.2d`**（double NEON），非 `v*.4s` |
| `NumericTraits<float>::RealType` | **`double`** — float 像素仍 double 算 |
| Bilateral 小图 float 加速 | **无**（0.98–1.01×），与 RecursiveGaussian 小图 ~2× 不同 |

**含义：** 改 `Image<float>` 主要 **减半内存**；在 ITK 默认实现下 **不要指望** 卷积类算子算力翻倍。

## 0. 方法说明（必读）

| 做了什么 | 没做什么 |
|----------|----------|
| **`+fp16`**：半精度 **存储**，读入 **`static_cast<float>` / `fcvt` 拓宽**，再 **FP32 加/乘** | **`fmlal` 指令**（`+fp16fml` 汇编失败） |
| 验证 **访存减半** 能否加速 BoxMean 等 | 用 fcvtl **替代** fmlal（二者功能不同） |

**fcvtl** = 类型转换；**fmlal** = FP16 乘加累加到 FP32。本 POC **只测前者路径**。

## 1. 实验目的

验证此前分析中的两个假设：

1. **FP16 存储 + FP32 累加**（`fcvtl` 拓宽）能否在 ITK 类盒式卷积上获得 **访存带宽** 收益；
2. **FMLAL**（`+fp16fml`）能否在本机鲲鹏环境编译并进一步加速 **乘加型** 卷积。

---

## 2. 实验设计

| 项目 | 设置 |
|------|------|
| 微基准程序 | `fp16_mean_microbench.cxx`（无 ITK 依赖） |
| 图像 | 合成 1024×1024 float；ITK 对照用 Brain PNG 放大 1024² |
| 邻域 | radius=15（31×31），与 `precision_conv_bench` 一致 |
| 线程 | OpenMP 96，`taskset -c 0-95` |
| 编译 | `-O3 -fopenmp -march=armv8.2-a+crypto+fp16` |
| FMLAL 编译 | 额外 `-march=...+fp16fml -DUSE_FP16FML` |

**三条内核路径：**

| 路径 | 说明 |
|------|------|
| F32_storage | float 像素，float 累加（基线） |
| F16_storage+FCVT+FP32 | float16 像素，读入后 `fcvtl` 到 float 再累加 |
| F16+FMLAL | `vfmlalq_low/high_f16` 累加到 FP32（需 fp16fml） |

## 3. 工具链结果

| 编译目标 | 结果 |
|----------|------|
| `+fp16`（fcvtl / ld1 half） | **成功** |
| `+fp16fml`（FMLAL intrinsic） | **失败** — `as 2.27` 不支持 `fp16fml` 扩展 |

```
Error: unknown architectural extension `fp16fml'
Error: unrecognized option -march=armv8.2-a+crypto+fp16fml
```

反汇编 `+fp16` 版可见 **`fcvtl v0.4s, v0.4h`**，确认半精度拓宽路径已生成；**无 `fmlal` 指令**。

## 4. 微基准实测（1024²，radius=15，5 runs）

### 4.1 BoxMean（31×31 邻域求和）

| 路径 | 耗时 (ms) | 相对 F32 | max_abs |
|------|-----------|----------|---------|
| F32_storage | **42.72** | 1.00× | — |
| F16_storage+FCVT+FP32 | **39.19** | **1.09×** | **0.055** |

（首次 run 曾测到 1.30×，两次 run 间有波动，均值为 **~1.1–1.3×**。）

**解读：** FP16 存储在大邻域盒滤波上主要省 **读带宽**；误差来自 FP16 量化（max_abs≈0.055）。

### 4.2 Gaussian 1D 行卷积（31 tap MAC）

| 路径 | 耗时 (ms) | 相对 F32 | max_abs |
|------|-----------|----------|---------|
| F32 MAC | **1.96** | 1.00× | — |
| F16+FCVT+FP32 MAC | **2.15** | **0.91×（更慢）** | **0.232** |
| F16+FMLAL MAC | **未测** | — | 工具链阻断 |

**解读：** 1D 31-tap 卷积 **算力/循环开销主导**，每像素仅读 31 次，FP16 读带宽优势被 **static_cast 拓宽 + 权重仍 float** 抵消；此场景 **FMLAL 即使能跑也难有收益**。

## 5. ITK 对照（同尺寸 1024²，96 线程）

| 算子 | ms_float | 说明 |
|------|----------|------|
| **Mean(radius=15)** | **3260.3** | ITK 通用 Mean，**极慢** |
| **BoxMean(radius=15)** | **65.9** | ITK BoxUtilities，与微基准同量级 |

**重要发现：** 同半径下 ITK `MeanImageFilter` 比 `BoxMeanImageFilter` 慢 **~50×**；FP16 优化应落在 **BoxMean** 路径。

微基准 F32 BoxMean **42.7 ms** vs ITK BoxMean **65.9 ms** — ITK 框架开销约 **+50%**。

---

## 6. 结论

| 问题 | 结论 |
|------|------|
| FP16 能否优化 ITK 类卷积？ | **部分能** — 大邻域 BoxMean **~1.1×**；小 tap Gaussian **无收益甚至更慢** |
| FMLAL 能否在本节点使用？ | **当前不能** — `as 2.27` 无法汇编 `fp16fml` |
| FMLAL 相对 FCVT+FP32 FMA 还能多多少？ | **Gaussian 已更慢，FMLAL 不值得优先**；BoxMean 上 FMLAL 对纯求和无意义（无乘法） |
| 是否值得 ITK fork？ | **ROI 中等** — 仅大图 BoxMean/卷积类；配准/PDE/FFT 不适用；需 FP16 IO + NumericTraits |
| 与现有 float 补丁关系？ | float 补丁解决 **double 累加**；FP16 解决 **读带宽** — 正交，可叠加但工程量大 |

## 2. 「混合精度」在 ITK 里指什么

ITK **没有** PyTorch/ GPU 那种「同一算子自动 FP16/BF16 + loss scaling」的全局混合精度框架。实际做法是：

1. **按像素类型选用模板参数**：例如存储用 **`float`**（省内存、带宽好），关键步骤用 **`double`**（减小累积误差）。  
2. **用 `itk::CastImageFilter`** 在滤波链上 **上升 / 下降精度**。  
3. **自定义滤波器** 内：中间变量用 **`double`** / **`RealType`**，输出再写回 **`float`**。

本仓库示例展示 **(2)**：**float 流水线 + 一段 double 高斯平滑 + 再 cast 回 float**，并与 **全程 float 平滑** 做数值对照（见下一节）。

## 3. 示例工程：`itk_hybrid_precision_demo`

### 3.1 位置

| 位置 | 路径 |
|------|------|
| 本地 | [`itk_hybrid_precision_demo/`](./itk_hybrid_precision_demo/) |
| 远端（第一台） | `/home/pub/yyq/itk_hybrid_precision_demo/` |

### 3.2 流水线说明

- **输入**：合成 **256×256** `float` 棋盘格图像。  
- **float**：`MedianImageFilter`。  
- **混合精度支路**：`Cast` → **`double`** → `SmoothingRecursiveGaussianImageFilter` → **`Cast` → `float`**。  
- **对照支路**：同一中值结果上 **`SmoothingRecursiveGaussianImageFilter<float>`**。  
- **输出指标**：  
  - **[A]** `double` 高斯结果 vs `float` 高斯结果逐像素差的 **`max_abs` / `mean_abs`**；  
  - **[B]** `double` 高斯结果 vs「混合支路最终 **float**」的差异（观察 **压回 float** 带来的量化）。

### 3.3 为何有时差异显示为 0

具体滤波器的 **内部实现** 可能对 **`float`/`double` 实例** 使用相近的数值路径或舍入方式；对特定合成数据，**[A]、[B] 可能都极小或为 0**。这不代表混合精度无意义，而是说明：**是否需要混合精度要以你的数据、滤波器组合和误差预算为准**。典型更需要 **`double`** 的阶段包括：**配准度量与优化**、**大范围动态数据**、**多步累积运算**等。

## 4. MPI + 真实体数据 + 混合精度：`mpi_hybrid_precision_demo`

在 **`mpi_itk_smoke`**（合成小图 + Median）基础上，本示例实现：**`itk::ImageFileReader<float,3>` 读真实体数据** → **按 MPI rank 划分子块** → **子块内混合精度高斯平滑** → **`MPI_Reduce` 汇总全局误差统计**。

### 4.1 路径

| 位置 | 路径 |
|------|------|
| 本地 | [`mpi_hybrid_precision_demo/`](./mpi_hybrid_precision_demo/) |
| 远端 | `/home/pub/yyq/mpi_hybrid_precision_demo/build/mpi_hybrid_precision_demo` |

### 4.2 命令行

```bash
mpi_hybrid_precision_demo <体数据路径> [sigma]
```

- **第 1 参数**：任意 ITK 可读 **3D** 标量体（实测 **`.mha` / `.mhd`**；工程链接 **Meta + PNG**，其它格式可按需增加 IO 模块）。  
- **第 2 参数**：高斯 **sigma**（默认 **1.5**）。

### 4.3 算法与实现要点（务必读）

1. **读入为 `float` 三维图像**（维度固定为模板 **`Dimension=3`**；若为纯 2D 文件，多数 IO 会读成 **单张切片的三维图**，仍可用）。  
2. **全局 pad**：若某一维尺寸 **&lt; 4**，先 **`itk::ConstantPadImageFilter`** 补零至至少 **4**，以满足 **`SmoothingRecursiveGaussianImageFilter`** 的硬性要求。  
3. **划分维度**：沿 **当前体积最长的一维** 切块（薄层数据避免沿层厚方向拆得过碎）。  
4. **子块 pad**：提取 ROI 后若仍有某维 **&lt; 4**，再对 **该 ROI** pad，避免多机切分后单层切片触发 ITK 报错。  
5. **混合精度**：每个子块上 **`Cast float→double`** → **`SmoothingRecursiveGaussian<double>`** → **`Cast→float`**（混合输出），并与 **全程 `float` 高斯** 对照；rank 0 打印 **`[D vs F]`**、**`[D vs H]`** 的全局 **`max_abs` / mean_abs**。  
6. **演示级内存模型**：当前实现 **每个 MPI rank 都整卷读入同一文件**，仅在计算上划分 ROI——**体数据很大时不要直接用于生产**；生产应改为 **单进程读 + 广播元数据**、**并行 IO** 或 **每进程只读自己负责的文件块**。

## 5. 与多机 MPI 的关系

- **混合精度**是 **单进程内像素类型与滤波链** 的设计问题。  
- **MPI 多机**是 **多进程** 问题；二者可叠加（每台进程内跑混合精度 ITK），手把手步骤见 [`操作记录_MPI双机环境与运行_2026-05-07.md`](./操作记录_MPI双机环境与运行_2026-05-07.md) **第 0 节**。

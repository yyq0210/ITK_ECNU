## 一、工作概述

本项目在 ITK 医学影像处理框架上开展**混合精度优化**，目标是在保证临床可接受精度的前提下，降低内存占用并提升计算性能。

优化分两个层次：

| 层次 | 做法 | 是否修改 ITK 源码 |
|------|------|-------------------|
| **应用层** | Pipeline 选用 `Image<float>`；配准保留 double 变换/度量/优化器 | 否 |
| **源码补丁层** | 将 Filter 内部 `RealType`（double）改为 `FloatType`（float）累加 | 是（维护 patch 脚本） |

**核心发现：** ITK 默认 `NumericTraits<float>::RealType = double`，多数 Filter 在 float 像素下仍用 double 做邻域运算；因此「只改像素类型」对大图卷积类算子加速有限，需结合源码补丁或选用 ITK 已内置 float 内部的算子（如 RecursiveGaussian）。

## 附录：什么是「补丁」？

### 1. 补丁是什么

**补丁（patch）** = 用脚本对 **ITK 官方源码** 做的小改动，不是改我们自己的 demo 程序。

| 对比 | 应用层优化 | 源码补丁 |
|------|-----------|----------|
| 改什么 | 你的程序里写 `Image<float>` | ITK 安装目录里的 `.h` / `.hxx` 头文件 |
| 典型操作 | `using ImageType = itk::Image<float, 2>;` | 把某行 `RealType` 改成 `FloatType` |
| 要不要重编 ITK | **不要** | **要**（改完源码后 `cmake --build`） |
| 升级 ITK 后 | 不受影响 | 补丁可能失效，需重新打 |

补丁脚本在 [`itk_float_accum_patches/`](./itk_float_accum_patches/)，每处改动带注释标记（如 `/* yyq: float accum */`），可用 `revert_*.sh` 一键还原。

### 2. 为什么要打补丁

ITK 里很多 Filter 虽然输入是 `Image<float>`，**内部计算仍用 double**：

```cpp
// ITK 默认写法（以 Bilateral 为例）
using OutputPixelRealType = NumericTraits<OutputPixelType>::RealType;  // float 像素 → RealType = double
```

结果是：图像占内存是 float（4 字节），但邻域乘加、累加在 CPU 上仍走 **double 指令**（ARM 上常见 `fmla v*.2d`），**算力省不下来**。

补丁做的事就是把这类 typedef 改成：

```cpp
using OutputPixelRealType = NumericTraits<OutputPixelType>::FloatType;  // 真正用 float 算
```

### 3. 三批补丁分别改了什么

| 批次 | 脚本 | 改了哪些文件 | 影响哪些算子 |
|------|------|-------------|-------------|
| **补丁 1** | `apply_patches.sh` | `itkBilateralImageFilter.h`<br>`itkMeanImageFilter.h`<br>`itkDiscreteGaussianImageFilter.h` | Bilateral、Mean、DiscreteGaussian 的**累加/邻域运算**改为 float |
| **补丁 2** | `apply_bilateral_full_float.sh` | 同上 Bilateral 的 `.h` + `.hxx` | 在补丁 1 基础上，把 Bilateral 的**域高斯核、值域查表（含 exp）、内层循环变量**也从 double 改为 float |
| **补丁 3** | `apply_patches_topn.sh` | `itkFiniteDifferenceFunction.h`<br>`itkFiniteDifferenceImageFilter.hxx`<br>`itkBoxUtilities.h` | **CAD/GAD** 等扩散类（改有限差分基类）+ **BoxMean** 盒滤波 |

**依赖关系：** 补丁 2 依赖补丁 1；补丁 3 也建议先打补丁 1。

**不需要补丁的例子：** `SmoothingRecursiveGaussianImageFilter` — ITK 源码里已经写了 `InternalRealType = FloatType`，所以 RecursiveGaussian 小图能到 ~2×，不是靠我们打的补丁。

### 4. 怎么用（远端 ITK 5.4.0）

```bash
# 打补丁
bash itk_float_accum_patches/apply_patches.sh              # 补丁 1
bash itk_float_accum_patches/apply_bilateral_full_float.sh  # 补丁 2（可选）
bash itk_float_accum_patches/apply_patches_topn.sh         # 补丁 3

# 重编受影响的 ITK 模块
cd /home/pub/yyq/ITK-5.4.0/build-yyq
cmake --build . --target ITKImageFeature ITKSmoothing ITKCommon ITKAnisotropicSmoothing-all -j96

# 还原（按相反顺序）
bash itk_float_accum_patches/revert_patches_topn.sh
bash itk_float_accum_patches/revert_bilateral_full_float.sh
bash itk_float_accum_patches/revert_patches.sh
```

### 5. 补丁实际带来了什么

| 预期 | 实际情况 |
|------|----------|
| float 算力 2× | **未达到**。补丁 1–3 对卷积类多为 **~1–7%** 墙钟提升 |
| 原因 | 大图 Bilateral 等仍**内存带宽瓶颈**；部分路径（如 exp）不在热循环 |
| 精度 | Bilateral/Mean/BoxMean 等 **max_abs≈0**；CAD 50 次迭代 **max_abs≈20**，需谨慎 |

**结论：** 补丁是「深入 ITK 内部、让 float 像素真正用 float 算」的**实验性手段**；**生产默认仍推荐应用层 `Image<float>`**（RecursiveGaussian、配准 float 存储 + double 度量等），补丁按算子收益可选叠加。

|----------|-------------------|----------|------|----------------------------|------|
| **ITKSmoothing** | `MeanImageFilter` | 源码补丁 1 | ✅ 完成 | ~**1.02–1.04×**（1024²） | max_abs ≈ 1e-5 |
| **ITKSmoothing** | `DiscreteGaussianImageFilter` | 源码补丁 1 | ✅ 完成 | ~**1.03–1.07×** | max_abs ≈ 1e-5 |

| **ITKSmoothing** | `SmoothingRecursiveGaussianImageFilter` | **ITK 原生**（`InternalRealType=FloatType`） | ✅ 无需 patch | **1.2–2.1×**（2D 小图） | max_abs = 0 |
| **ITKImageFeature** | `BilateralImageFilter` | 源码补丁 1 + 2 | ✅ 完成 | ~**1.01–1.02×**（1024²–2048²） | max_abs = 0 |
| **ITKCore / ITKFiniteDifference** | `FiniteDifferenceFunction`（基类） | 源码补丁 3 | ✅ 完成 | 见下方扩散算子 | 见下方 |

### 2.2 按优化方式分类

#### A. 应用层优化（零 ITK 源码修改，**推荐生产默认**）

| 模块 | 算子 | 结论 |
|------|------|------|
| ITKSmoothing | RecursiveGaussian、Median、DiscreteGaussian | 全程 `Image<float>`，2D 真实数据 **1.2–2.1×** 加速，精度无损 |
| ITKThresholding | Otsu | 全程 float，**1.2–1.3×**，精度无损 |
| ITKRegistrationMethodsv4 | Metricsv4 + Optimizer v4 | **float 图像 + double 变换/度量/优化器**（同 ITK 官方 ImageRegistration1），**~1.36×** |
| ITKImageFeature | Bilateral | 应用层 float 主要 **省内存**；大图算力加速需叠加源码补丁 |

**已明确放弃：** cast 链 hybrid（float→double→Filter→float），实测 **比 full_double 更慢**。

#### B. ITK 源码补丁（三批，标记 `yyq: float accum` 等）

| 批次 | 修改文件 / 模块 | 覆盖算子 |
|------|----------------|----------|
| **补丁 1** | `itkBilateralImageFilter.h`、`itkMeanImageFilter.h`、`itkDiscreteGaussianImageFilter.h` | Bilateral、Mean、DiscreteGaussian |
| **补丁 2** | `itkBilateralImageFilter.h/.hxx`（域核、查表、内层循环） | Bilateral 全路径 float |
| **补丁 3** | `itkFiniteDifferenceFunction.h`、`itkFiniteDifferenceImageFilter.hxx`、`itkBoxUtilities.h` | CAD、GAD 及所有有限差分类 Filter；BoxMean |

补丁脚本目录：[`itk_float_accum_patches/`](./itk_float_accum_patches/)

#### C. ITK 原生已优化（无需改动）

| 模块 | 说明 |
|------|------|
| **ITKSmoothing** | `SmoothingRecursiveGaussianImageFilter` 内部已设 `InternalRealType = FloatType`，是小图 **~2×** 加速的主要原因 |

## 三、未完成 / 未纳入本轮优化的模块

| ITK 模块 | 原因 |
|----------|------|
| **Resample / 插值** | 扫频中单线程仅 ~0.03 s，非热点；插值路径非 RealType 累加瓶颈 |
| **全局 NumericTraits** | 影响面过大，未做 |
| **BF16 / FP16 像素类型** | 需 ITK fork 级改造，列为远期 |
| **`ITK_USE_FLOAT_SPACE_PRECISION`** | 仅影响 spacing/origin 等元数据，**未实测** |
| **Level-set / 其它 FiniteDifference 算子** | 补丁 3 已改基类，但**未逐一 benchmark**；CAD 显示迭代误差增大，需谨慎 |
| **GPU 模块（ITKGPU*）** | 未涉及 |

## 五、生产推荐配置

```
读入 Image<float>
  ├─ 滤波 / 分割：float Filter（RecursiveGaussian 等优先）
  │     └─ 可选：应用 ITK 源码补丁 1–3（卷积类 ~1–7% 额外收益）
  ├─ 配准：Image<float> + TranslationTransform<double> + Metricv4<double>
  └─ 写回 float / 按需 Cast
```

**不推荐：** hybrid cast 链；全局无差别 `Image<double>`→float；对 CAD 盲目使用补丁 3 而不做精度验证。

## 七、汇报用一句话总结

**已完成混合精度优化的 ITK 模块主要包括：ITKSmoothing（Mean、DiscreteGaussian、BoxMean、RecursiveGaussian）、ITKImageFeature（Bilateral）、ITKFiniteDifference / ITKAnisotropicSmoothing（CAD/GAD）、ITKRegistrationMethodsv4（应用层 float 存储 + double 度量）及 ITKThresholding（Otsu）；其中应用层 float 化在 2D 滤波上可达 1.2–2.1× 加速且精度无损，源码补丁对卷积类算子额外带来约 1–7% 收益，配准 float 存储约 1.36× 加速；Bilateral 大图与 CAD 迭代类算子仍受内存带宽或数值累积限制，不宜期望 2× 算力提升。**

## 八、后续工作建议

1. 对 CAD 补丁 3 做视觉/指标级验收，或生产环境保留 double 内部演算。

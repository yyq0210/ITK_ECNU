## 2. 环境探测（会话中实际命令与结果）

### 2.1 工具链与 CPU

```bash
/home/pub/gjj/gcc10/bin/g++ --version   # g++ (GCC) 10.1.0
as --version                            # GNU assembler version 2.27-44.base.el7
lscpu | grep -E 'Architecture|Flags'    # aarch64；Flags 中含 fp asimd … asimddp …
```

**要点：** GCC **10** 与系统 **`as` 2.27** 来自 **不同年代**；**`-march=native`** 由 GCC 选择的 ISA 字符串可能 **超出旧 `as` 的解析能力**。

### 2.2 **`-march=native`** 失败复现（勿在生产配置中使用）

```bash
printf '%s\n' 'int main(){return 0;}' > /tmp/neon_test.cpp
/home/pub/gjj/gcc10/bin/g++ -O3 -march=native -c /tmp/neon_test.cpp -o /tmp/neon_test.o
```

**典型报错（节选）：**

```text
Assembler messages:
Error: unknown architectural extension `dotprod+fp16fml'
Error: unrecognized option -march=armv8.2-a+crypto+dotprod+fp16fml
```

### 2.3 安全 **`march`** 探测

以下在 **`/tmp/neon_test.cpp`** 上 **编译成功**：

- **`-march=armv8-a`**
- **`-march=armv8.2-a`**
- **`-march=armv8.2-a+crypto`**

以下 **失败**（`as` 不识 **`dotprod`**）：

- **`-march=armv8.2-a+dotprod`**

### 2.4 向量化烟雾测试（非 ITK，仅证明 **march + O3** 出 NEON）

```bash
printf '%s\n' '#include <cstddef>' 'float a[256],b[256],c[256];' 'void foo(){ for(size_t i=0;i<256;i++) c[i]=a[i]*b[i]+1.0f; }' > /tmp/vec.cpp
/home/pub/gjj/gcc10/bin/g++ -O3 -march=armv8.2-a+crypto -c /tmp/vec.cpp -o /tmp/vec.o
objdump -d /tmp/vec.o | grep fmla
```

**示例输出（节选）：** 出现 **`fmla v0.4s, v2.4s, v1.4s`**，表明 **ASIMD** 浮点乘加已向量化。

## 3. 对 ITK `build-yyq` 已执行的操作

### 3.1 工作目录

**`/home/pub/yyq/ITK-5.4.0/build-yyq`**（既有成功配置，本次为 **重配 + 增量重编**）。

### 3.2 CMake 重配置（写入全局 C/C++ 标志）

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq

env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake /home/pub/yyq/ITK-5.4.0 \
  -DCMAKE_CXX_FLAGS=-march=armv8.2-a+crypto \
  -DCMAKE_C_FLAGS=-march=armv8.2-a+crypto
```

**预期：** **`CMakeCache.txt`** 中：

- `CMAKE_CXX_FLAGS:STRING=-march=armv8.2-a+crypto`
- `CMAKE_C_FLAGS:STRING=-march=armv8.2-a+crypto`  

某模块的 **`flags.make`** 中 **`CXX_FLAGS`** 应含 **`-march=armv8.2-a+crypto`** 与 **`-O3 -DNDEBUG`**（Release）。

### 3.3 已执行的增量编译目标

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq
env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake --build . --target ITKCommon -j24

env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake --build . --target ITKSmoothing -j24

env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
```

**结果：** 上述 target **均 `Built target ...` 成功**；**`BilateralImageFilter`** 连带触发大量依赖库在 **新标志** 下重编/链接。

### 3.4 ITK 产物上的向量化核查（示例）

```bash
objdump -d /home/pub/yyq/ITK-5.4.0/build-yyq/Examples/Filtering/CMakeFiles/BilateralImageFilter.dir/BilateralImageFilter.cxx.o \
```

## 4. 后续建议（全量一致与升级路径）

### 4.1 全量重编（推荐在维护窗口执行）

当前 **仅保证** 已触达目标及其依赖链在新 **`march`** 下重编；**其余静态库 `.a` 内仍可能混有旧 `.o`**。若要求 **整树一致**：

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq
env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake --build . -- -j96
```

### 4.2 从零新建 `build-yyq` 时

在首次 **`cmake ..`** 中与其它选项一并加入：

```text
-DCMAKE_CXX_FLAGS=-march=armv8.2-a+crypto
-DCMAKE_C_FLAGS=-march=armv8.2-a+crypto
```

完整示例仍见 [`操作记录_ITK编译与单节点并行绑核_2026-05-07.md`](./操作记录_ITK编译与单节点并行绑核_2026-05-07.md) **§3.3**。

### 4.3 若将来要使用 **`-march=native`**

1. 在节点安装 **较新 binutils**（使 **`as`** 支持 GCC 为 **`native`** 选中的扩展）。  
2. 确保 **`PATH`** 中 **`as`** 优先为新版本（或让 GCC 使用自带集成汇编路径，视安装方式而定）。  
3. 再评估是否恢复 **`/etc/profile.d/kunpeng-simd.sh`** 一类全局 **`CFLAGS`**。

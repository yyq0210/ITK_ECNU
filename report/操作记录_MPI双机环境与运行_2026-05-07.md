## 0. 新手手把手：多机运行 ITK 示例（`/mpi_itk_smoke`）

本节假设你会用 **`ssh` 登录 Linux 服务器**，并对 **`scp` 有基本概念**。全程只需在 **第一台（202.120.87.20）** 上敲命令（除非特别说明要在自己电脑上上传文件）。

### 0.1 一句话说清楚：你在干什么

- **ITK** 本身主要是在 **一台机器的一个进程里** 用多线程算图像。  
- **多机** = 用 **MPI** 同时启动 **多台机器上的多个进程**；每个进程里可以再跑 ITK。  
- 本文档里的 **`mpi_itk_smoke`** = **最小的演示程序**：每个进程都做一点 ITK 计算，再用 MPI 把结果汇总——用来确认 **「两台机器 + MPI + ITK」链路是通的**。  
- **真实课题**（例如一大张图拆成两半分别在两台算）还需要你自己写 **数据怎么分、结果怎么合并**，那是下一步，不在本示例里。

**谁在干什么（示意图）：**

```text
  你的电脑                     第一台 (202.120.87.20, hpc01)              第二台 (202.120.87.128, hpc03)
  ---------                     ----------------------------              ------------------------------
      |                                      |                                       ^
      | ssh                                  | mpirun 通过 SSH 远程启动进程          |
      v                                      +--------------------------------------+
  [可选：scp 上传源码/脚本]                   |  本机也会跑若干个 MPI 进程            |
                                             v                                       v
                                       mpi_itk_smoke                         mpi_itk_smoke
                                       （路径两台必须相同）                  （同左）
```

### 0.2 必备概念（看不懂命令时翻这里）

| 名词 | 白话 |
|------|------|
| **第一台 / 第二台** | IP **`202.120.87.20`**（也叫 hpc01）和 **`202.120.87.128`**（也叫 hpc03）。**你只要记住：命令几乎都在第一台敲。** |
| **`mpirun`** | 「帮我在多台机器上启动好几个进程」的命令；后面要跟 **主机列表**、**进程个数**、**要运行的程序路径**。 |
| **hostfile** | 一个文本文件，里面写 **哪些 IP 参与**、每台最多起多少个进程（**slots**）。本文用 **`/home/pub/yyq_archive/mpi_hosts_2nodes.txt`**。 |
| **`-np 8`** | 一共启动 **8 个** MPI 进程（不是 8 台机器；这里是 8 个进程分布在两台机上）。 |
| **`--map-by node`** | **轮流往两台机器上放进程**，避免「进程太少时全跑在第一台」导致你以为第二台没参与。 |
| **`--allow-run-as-root`** | 若你用 **root** 账号跑 `mpirun`，Open MPI 要求加这个开关（实验环境常见；正规集群建议用普通用户）。 |
| **rank** | 每个 MPI 进程的编号（0, 1, 2, …）；程序里用来区分「我是第几个进程」。 |
| **为什么两台路径要一样？** | 没有共享磁盘时，第二台必须在 **完全相同的路径** 下也能找到那个可执行文件，例如两台都有 **`/home/pub/yyq/mpi_itk_smoke/build/mpi_itk_smoke`**。 |

**步骤 3 — 发起多机运行（root 示例）：**

```bash
mpirun --allow-run-as-root \
  --hostfile /home/pub/yyq_archive/mpi_hosts_2nodes.txt \
  --map-by node \
  -np 8 \
  /home/pub/yyq/mpi_itk_smoke/build/mpi_itk_smoke
```

**步骤 4 — 怎样算成功？**

- 终端里会出现 **多行** `rank ... on hpc01` 或 `... on hpc03`。  
- **必须同时看到 `hpc01` 和 `hpc03`**（或对应两台主机名），才算「真的双机都跑了」。  
- **`rank 0` 那一行附近**会有 **`itk_median_global_pixel_sum=...`**，表示 MPI 汇总成功。

若 **只有 hpc01、没有 hpc03**：检查是否加了 **`--map-by node`**；或把 **`-np`** 改大一点（例如 8）。

### 0.7 限制 ITK 线程数（避免「进程太多把 CPU 挤爆」）

每个 MPI 进程内部，ITK 还会起线程。进程很多时，建议在 **`mpirun` 前** 加上（数字可按机器调整）：

```bash
export ITK_GLOBAL_DEFAULT_THREADER=Pool
export ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS=4
```

然后再执行 **0.4 步骤 3** 的 `mpirun` 命令。

### 0.9 小白常见报错（对照处理）

| 报错或现象 | 最常见原因 | 怎么做 |
|------------|------------|--------|
| `could not execute ... Node: 202.120.87.128` | 第二台 **没有** 同路径可执行文件 | 重做 **0.4 步骤 2** |
| `GLIBCXX_3.4.xx not found` | 第二台 **libstdc++ 太旧**，而你拷过去的程序 **没有静态嵌入** C++ 库 | 在第一台 **重新 cmake 编译** `mpi_itk_smoke`（确保 `CMakeLists.txt` 含 `-static-libstdc++`），再 **scp 覆盖** 第二台 |
| 输出里 **只有 hpc01** | 进程数少且 **未** `--map-by node` | 加上 **`--map-by node`** 或增大 **`-np`** |
| `Running as root is strongly discouraged` | root 跑 Open MPI | 加上 **`--allow-run-as-root`**，或换 **非 root** 用户并去掉该参数 |
| `ssh ... Host key verification failed`（从第二台连第一台） | known_hosts 未配置 | 多机作业 **只在第一台发起** 即可；若必须从第二台发起，再找管理员配置 SSH |

## 6. Open MPI 多机运行方式

### 6.1 前置条件小结

1. **两端 MPI 主版本一致**（已为 **4.0.1**）。  
2. **发起节点到各计算节点的 SSH 无交互登录**（已从第一台连第二台验证）。  
3. **无共享文件系统时**：可执行文件必须在 **各节点相同绝对路径** 存在（见 6.4）。  
4. **root 运行**：Open MPI 会拒绝默认 root，需要 **`--allow-run-as-root`**；生产环境建议改为 **非 root** 用户。

### 6.2 hostfile 内容

文件：**`/home/pub/yyq_archive/mpi_hosts_2nodes.txt`**（本地副本：`mpi_hosts_2nodes.txt`）

```text
202.120.87.20 slots=96
202.120.87.128 slots=96
```

### 6.3 进程映射：`--map-by node`

- **默认 filling**：往往 **先占满第一台**，再使用第二台；仅用少量进程时可能 **全部落在第一台**。  
- **`--map-by node`**：**按节点轮转** 分配 rank，便于验证 **双机都在跑**（当日用 **`-np 8`** 的 **`hostname`** / **`hello_mpi`** 已看到 **hpc01 与 hpc03** 均有输出）。

### 6.4 同步可执行文件到第二台（无共享盘时必做）

在第一台编译出 `hello_mpi` 后，需拷到第二台 **相同路径**，示例：

```bash
scp root@202.120.87.20:/home/pub/yyq_archive/hello_mpi \
    root@202.120.87.128:/home/pub/yyq_archive/hello_mpi
ssh root@202.120.87.128 "chmod +x /home/pub/yyq_archive/hello_mpi"
```

否则 `mpirun` 会在远程节点上报 **无法执行指定 Executable**。

### 6.5 在第一台发起：示例命令

**（1）查看进程落在哪些节点（8 进程）：**

}

## 7. 与 ITK 多机使用的衔接说明

- **MPI 多机**解决的是：**多个 OS 进程 / 多个节点** 的协同。  
- **ITK** 在单进程内用 **线程池** 做数据并行；**跨节点**不会自动发生，需要 **MPI 程序在外层** 切分数据、通信、汇总，或在各 rank 上独立跑完整小块流水线。  
- 多机跑 **同一可执行文件** 时：无共享盘则需在 **各节点相同绝对路径** 放置二进制；并注意 **`LD_LIBRARY_PATH` / `libstdc++` 版本**（见第 8 节）。  
- 运行时建议设置 **`ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS`**，避免 **MPI 进程数 × ITK 线程数** 过度订阅 CPU。

## 10. 故障与后续可做事项

**提示：** 报错先看 **第 0.9 节「小白常见报错」**；下表为简明索引（面向所有人）。

| 现象 | 可能原因 | 处理方向 |
|------|----------|----------|
| 远程节点无法执行 binary | 第二台缺少同路径可执行文件 | `scp`/`rsync` 同步并 `chmod +x` |
| `GLIBCXX_*` / `CXXABI_*` not found | 第二台 **libstdc++** 过旧 | 使用 **`-static-libstdc++`**（本示例已采用），或在第二台配置与第一台一致的 **GCC lib 路径** + `LD_LIBRARY_PATH` |
| 所有 rank 都在第一台 | 进程数少且默认 filling | 使用 **`--map-by node`** 或增加 `-np` |
| root 无法 `mpirun` | Open MPI 安全限制 | **`--allow-run-as-root`** 或改用普通用户 |
| 从第二台发起失败 | 反向 SSH / known_hosts | 配置 **hpc03 → hpc01** 免密与 host key |
| 第二台无法 cmake ITK | CMake/GCC 过旧 | 安装 **CMake ≥ 3.16.3**、较新 GCC，或同步 **`build-yyq`** |

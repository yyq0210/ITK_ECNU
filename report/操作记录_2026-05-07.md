## 1. 背景说明（与本记录相关的约束）

- 远端系统为 CentOS 一类环境，**glibc 较旧（约 2.17）**，无法满足当前 **VS Code Server / Cursor Remote SSH** 对 glibc 的要求（通常需 **≥ 2.28**），因此无法在远端直接挂编辑器服务端。
- **推荐工作方式：** 在本地（Cursor 等）改代码，通过 **Git / rsync / scp + 普通 SSH** 在远端编译与运行。
- 硬件 SIMD：aarch64 上 **ASIMD**（常被称作 NEON 类向量能力）由 CPU 特性标志体现（如 `asimd`、`asimddp`），**无需在 BIOS 里单独“打开 NEON”**；要在**自编译程序**里用上，主要依赖编译选项（见第 4 节）。

## 3. SSH 公钥登录配置要点

首次在本环境用 **BatchMode** 自动化 SSH 时曾因未配置密钥而失败；你在远端 **`root`** 账户配置公钥后，自动化命令可正常执行。

**是否会覆盖他人公钥：**

- 使用 **`>>` 追加** 到 `/root/.ssh/authorized_keys`，或使用 **`ssh-copy-id`**（默认追加），**一般不会删除**已有行。
- 若使用 **`>` 覆盖整个文件**，或编辑时删掉他人行，则会**导致他人无法登录**。

**建议自检：**

```bash
wc -l /root/.ssh/authorized_keys
cat /root/.ssh/authorized_keys
```

**权限：** `/root/.ssh` 建议 `700`，`authorized_keys` 建议 `600`。

## 4. 编译侧“向量化 / SIMD”启用（Kunpeng / aarch64）

### 4.1 硬件与编译器探测（当时远端状态摘要）

- **`lscpu`：** aarch64，多核；CPU 特性中含 **`fp`、`asimd`、`asimddp`** 等。
- **GCC：** 10.1.0（示例路径前缀含 `/home/pub/gjj/gcc10`）。
- **`gcc -march=native`（`-Q --help=target`）：** 约为 **`armv8.2-a+crypto+dotprod+fp16fml`**（随机器与 GCC 版本可能略有差异）。

### 4.2 已在远端部署的全局脚本

**路径：** `/etc/profile.d/kunpeng-simd.sh`

**作用：** 在 **登录 shell** 且未设置 **`NO_KUNPENG_SIMD_CFLAGS`** 时，为 **`CFLAGS`、`CXXFLAGS`** 前置 **`-O3 -march=native`**，便于 GCC 针对本机 ISA 做优化与向量代码生成。

**关闭（单次会话）：**

```bash
export NO_KUNPENG_SIMD_CFLAGS=1
```

**注意：**

1. **`-march=native` 生成的二进制可能无法在更老的 ARM 上运行**，仅适合“在本机跑最快”的场景。
2. **非登录**的一次性远程命令（如 `ssh host 'make'`）可能**不会**加载 `/etc/profile.d`；若作业脚本里编译，请显式：`source /etc/profile.d/kunpeng-simd.sh`，或在 CMake 中传入 `-DCMAKE_C_FLAGS` / `-DCMAKE_CXX_FLAGS`。

本目录下附带 **`kunpeng-simd.sh`**，与远端 `/etc/profile.d/kunpeng-simd.sh` 内容一致，便于备份或重做部署（见 `scp` 示例）。

**部署或覆盖远端脚本示例：**

```powershell
scp D:\ECNU_HPC\ITK_huawei\kunpeng-simd.sh root@202.120.87.20:/etc/profile.d/kunpeng-simd.sh
ssh root@202.120.87.20 "chmod 644 /etc/profile.d/kunpeng-simd.sh"
```

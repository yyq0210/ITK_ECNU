## 1. 结论先行：OpenMP 变量与 ITK 5.4 并行

| 机制 | 作用对象 |
|------|----------|
| `OMP_NUM_THREADS`、`OMP_PROC_BIND=true`、`OMP_PLACES=cores` | **仅**对程序中 **OpenMP 并行区域**或链接 **libgomp** 且含 OpenMP 指令的代码生效。 |
| **ITK 5.4 默认多线程** | 实现类型为 **Pool（pthread）**、**TBB**、**Platform** 之一（CMake 中 `ITK_DEFAULT_THREADER` 可选：`Auto;TBB;Pool;Platform`），**没有 OpenMP threader**。 |
| **控制 ITK 滤波器等内部并行** | 环境变量 **`ITK_GLOBAL_DEFAULT_THREADER`**（如设为 `Pool`）与 **`ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS`**（如 `96`）；另有历史兼容变量 **`ITK_USE_THREADPOOL`**（已弃用，仍会提示改用 `ITK_GLOBAL_DEFAULT_THREADER`）。 |
| **pthread 工作线程绑核** | **`OMP_PROC_BIND` 无法绑定 ITK Pool 的 pthread**；若要对整进程（含子线程继承亲和性）绑核，宜用 **`taskset -c 0-95`** 或 **`numactl`** 等在进程级限定 CPU 集合。 |

**实践建议：** 若同时使用外层 OpenMP 与 ITK 多线程，注意避免过度嵌套并行（例如一侧设为 1 线程、另一侧拉满）。

## 3. 新构建目录 `build-yyq`：工具链与配置要点

### 3.1 CMake 与编译器版本

- 系统 `/usr/local/bin/cmake` 为 **3.6.2**，**不满足** ITK 5.4 要求的 **CMake ≥ 3.16.3**。
- 实际使用：**`/home/pub/cmake/bin/cmake`（3.27.1）**。
- C/C++ 使用：**`/home/pub/gjj/gcc10/bin/gcc` / `g++`（10.1.0）**。
- **`gmake`：** `/usr/bin/gmake`；配置时需保证 **`PATH`** 含 `/usr/bin`，否则 CMake 找不到 `CMAKE_MAKE_PROGRAM`。

### 3.2 `kunpeng-simd.sh` 与 `-march=native` 导致的编译失败

在默认登录环境（加载 `/etc/profile.d/kunpeng-simd.sh`）下，`CFLAGS`/`CXXFLAGS` 可能含 **`-O3 -march=native`**。  
当前组合下 GCC 产出的 **`armv8.2-a+crypto+dotprod+fp16fml`** 等选项与系统 **汇编器（as）** 能力不匹配，导致 **CMake 编译器探测阶段即失败**，典型报错包含：

- `unknown architectural extension 'dotprod+fp16fml'`
- `unrecognized option -march=armv8.2-a+crypto+dotprod+fp16fml`

**处理方式：** 在**配置与编译** ITK 时使用 **洁净环境**，避免继承上述标志，例如：

- `env -i HOME=/root PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin ...`

单独设置 `NO_KUNPENG_SIMD_CFLAGS=1` 在部分登录脚本仍注入标志时可能不够，**以实际环境中是否仍带 `-march=native` 为准**。

### 3.3 CMake 配置参数（与此前静态 Release 构建对齐）

在 **`/home/pub/yyq/ITK-5.4.0/build-yyq`** 中执行（示例）：

```bash
rm -rf /home/pub/yyq/ITK-5.4.0/build-yyq
mkdir -p /home/pub/yyq/ITK-5.4.0/build-yyq
cd /home/pub/yyq/ITK-5.4.0/build-yyq

env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake .. \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=/home/pub/gjj/gcc10/bin/gcc \
  -DCMAKE_CXX_COMPILER=/home/pub/gjj/gcc10/bin/g++ \
  -DCMAKE_MAKE_PROGRAM=/usr/bin/gmake \
  -DBUILD_SHARED_LIBS=OFF \
  -DBUILD_STATIC_LIBS=ON \
  -DBUILD_TESTING=OFF \
  -DBUILD_EXAMPLES=ON \
  -DITK_DEFAULT_THREADER=Pool \
  -DCMAKE_INSTALL_PREFIX=/usr/local \
  -DCMAKE_CXX_FLAGS=-march=armv8.2-a+crypto \
  -DCMAKE_C_FLAGS=-march=armv8.2-a+crypto
```

说明：

- **最后两行（`CMAKE_*_FLAGS`）**：**NEON/ASIMD 安全向量化**（原理与 **`native` 替代方案** 见 **§3.5**）；若工具链已支持 **`native`**，可改为环境推荐的 **`march`** 或省略。  
- **`BUILD_EXAMPLES=ON`**：生成 `build-yyq/bin/` 下大量可执行示例，便于验证并行与 IO。  
- **`ITK_DEFAULT_THREADER=Pool`**：编译期默认线程实现为 Pool（与运行时 `ITK_GLOBAL_DEFAULT_THREADER=Pool` 一致）。

### 3.4 编译命令

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq
env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake --build . -- -j96
```

已在该环境下完成一次成功构建（示例二进制出现在 **`build-yyq/bin/`**）。

### 3.5 aarch64 上开启 NEON（ASIMD）且仍能稳定编译 ITK

**独立操作记录（含环境探测命令、失败/成功日志与全量重编建议）：** [`操作记录_ITK_NEON向量化安全编译_2026-05-13.md`](./操作记录_ITK_NEON向量化安全编译_2026-05-13.md)。

**背景：** AArch64 的 SIMD 即 **ASIMD（常称 NEON）**。GCC 在 **`-O3`** 下会做自动向量化；是否生成 **`fmla` / `xtn` / `v*.4s`** 等指令，还取决于 **`-march=…`** 是否被 **系统汇编器 `as`** 接受。

**本机实测（`202.120.87.20`）：** GCC **10.1.0** + 系统 **`as` 2.27**（RHEL7 系）。**`-march=native`** 会展开为含 **`dotprod` / `fp16fml`** 的子扩展，**与 binutils 2.27 不兼容**，报错同 §3.2。

**可行方案（已在 `build-yyq` 上执行）：** 使用 **`armv8.2-a+crypto`**（不启用 **`+dotprod`** 等汇编器不识别的扩展），与 **`-O3`** 合并后仍可产生 **NEON/ASIMD** 指令：

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq

env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake /home/pub/yyq/ITK-5.4.0 \
  -DCMAKE_CXX_FLAGS=-march=armv8.2-a+crypto \
  -DCMAKE_C_FLAGS=-march=armv8.2-a+crypto
```

配置成功后 **`CMakeCache.txt`** 中 **`CMAKE_CXX_FLAGS` / `CMAKE_C_FLAGS`** 应为上述字符串；**`Modules/.../flags.make`** 中可见 **`-march=armv8.2-a+crypto`** 与 **`-O3 -DNDEBUG`** 并存。

**验证：** 增量重编 **`BilateralImageFilter`** 后，对 **`Examples/Filtering/CMakeFiles/BilateralImageFilter.dir/BilateralImageFilter.cxx.o`** 执行 **`objdump -d`**，可见 **`xtn ... v*.4s`** 等 **ASIMD** 指令。

**同次会话已重编目标：** **`ITKCommon`**、**`ITKSmoothing`**、**`BilateralImageFilter`**。若需 **整库所有目标文件** 均带统一 **`march`**，请在维护窗口执行全量：

```bash
cd /home/pub/yyq/ITK-5.4.0/build-yyq
env -i HOME="$HOME" PATH=/home/pub/gjj/gcc10/bin:/home/pub/cmake/bin:/usr/bin:/usr/local/bin \
  cmake --build . -- -j96
```

**将来若要 `-march=native`：** 安装 **较新 binutils** 并令 **`PATH`** 优先使用新 **`as`**，再考虑 **`native`** 或 **`kunpeng-simd.sh`**。

**从零新建 `build-yyq` 时：** 在 §3.3 的首次 **`cmake ..`** 中追加 **`-DCMAKE_CXX_FLAGS=-march=armv8.2-a+crypto -DCMAKE_C_FLAGS=-march=armv8.2-a+crypto`** 即可。

## 4. 运行方式（单机）：环境变量 + 进程绑核

### 4.0 操作顺序（端到端）

1. **登录第一台节点**（示例：`ssh root@202.120.87.20`；生产环境建议用 **`pub`** 等非 root 账号）。  
2. **确认 ITK 已在本机构建完成**，示例二进制存在：  
   `/home/pub/yyq/ITK-5.4.0/build-yyq/bin/BilateralImageFilter`。  
3. **选择一种运行方式**（任选其一）：  
   - **命令行**：按下面 **4.2** 设置环境变量后直接执行滤波器；  
   - **绑核**：按 **4.3** 使用 **`taskset`**（OpenMP 的 `OMP_PROC_BIND` **不能**绑定 ITK 的 pthread 线程）；  
   - **脚本**：将 [`run_itk_single_node_bind.sh`](../run_itk_single_node_bind.sh)（仓库根目录 `ITK_huawei`）**scp** 到远端 **`/home/pub/yyq/`**，执行 **`sed -i 's/\r$//'`** 去 CRLF 后 **`chmod +x`** 运行（见 **第 5 节**）。  
4. **核对输出文件**（示例中为 **`/tmp/bilateral_out.png`**）是否生成。

### 4.1 示例程序与数据

- **可执行文件：** `/home/pub/yyq/ITK-5.4.0/build-yyq/bin/BilateralImageFilter`
- **用法：**  
  `BilateralImageFilter inputImageFile outputImageFile domainSigma rangeSigma`
- **示例输入：** `/home/pub/yyq/ITK-5.4.0/Examples/Data/BrainProtonDensitySlice256x256.png`
- **示例输出：** 如 `/tmp/bilateral_out.png`

### 4.2 手动一行命令（OpenMP + ITK 线程 + 运行）

```bash
export OMP_NUM_THREADS=96 OMP_PROC_BIND=true OMP_PLACES=cores
export ITK_GLOBAL_DEFAULT_THREADER=Pool ITK_GLOBAL_DEFAULT_NUMBER_OF_THREADS=96

/home/pub/yyq/ITK-5.4.0/build-yyq/bin/BilateralImageFilter \
  /home/pub/yyq/ITK-5.4.0/Examples/Data/BrainProtonDensitySlice256x256.png \
  /tmp/bilateral_out.png 4 50
```

### 4.3 绑核（推荐与 ITK pthread 配合）

对**整个进程**绑定到 0–95 号 CPU（按节点实际核数调整）：

```bash
taskset -c 0-95 /home/pub/yyq/ITK-5.4.0/build-yyq/bin/BilateralImageFilter \
  /home/pub/yyq/ITK-5.4.0/Examples/Data/BrainProtonDensitySlice256x256.png \
  /tmp/bilateral_out.png 4 50
```

可将 `export` 与 `taskset` 一并写入脚本（见第 5 节）。
